Architecture

Shader Protocol is a Groth16 shielded pool with a TypeScript client and thin chain adapters. The pieces below are in the repository. They are not deployed.

Transfer shape

  • One input note, two output notes, and a fee: value in = value out 1 + value out 2 + fee.
  • Commitments are Poseidon hashes of the note opening.
  • The nullifier is bound to the commitment and the leaf index.
  • extDataHash binds the recipient, the relayer, the fee, the chain, and the pool.
  • Public inputs are canonical field elements, in a fixed order.
  • Each pool keeps a root history. A proof must cite a root that history still holds.

Keys

Stealth addresses and regulator keys are secp256k1. The view key recognizes and decrypts. It does not derive the spending key used inside the circuit. The client class is still named ShadeClient until the code is renamed. The repository URL is still github.com/Chenz0-13/shade-protocol.

Canton trust assumption

Canton does not check a Groth16 proof. A record is accepted only when two named attestors authorize it. Those attestors are expected to report a spend that a pool already accepted. If two attestors sign a result that never happened, Canton stores it. That is an attestation, not a proof check. The TypeScript adapter does not submit.

Not in this build

HyperEVM testnet, Base Sepolia, a v2 universal note format, private cross-chain teleport (two transports must agree, with per-epoch caps), disclosure receipts, agent allowance notes, private payroll, a multi-party ceremony, and a CI security toolchain are in development. They are not shipped.
