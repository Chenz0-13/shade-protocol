Security

Single-party development setup. Not audited. Devnet and testnet only. No mainnet deployment.

Report a vulnerability

Use GitHub private vulnerability reporting. Do not open a public issue for an unfixed security bug. Include what you did, the code path, and a proof of concept if you have one.

https://github.com/Chenz0-13/shade-protocol/security/advisories/new

There is no bug bounty.

What is not safe

  • Groth16 keys from the development setup are a single-party setup. Anyone who kept the intermediate parameters can forge proofs.
  • The commitment tree depth is a devnet limit, not a production size.
  • The operator matcher can read orders it opens. It is not a custody design.
  • The devnet screening default checks nobody.
  • Zero-knowledge KYC proofs are not implemented.
  • Canton records a 2-of-N attestation. Two attestors can record a spend a pool never accepted. Canton does not verify the proof.
  • No adapter on this list is deployed.

Planned path

No dates are promised.

  1. Multi-party trusted setup ceremony.
  2. Independent audit.
  3. Guarded beta with caps, only after the ceremony and the audit.

The code is not audited today. A guarded beta is not a mainnet launch.
